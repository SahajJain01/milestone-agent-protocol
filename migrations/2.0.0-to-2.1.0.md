# Migrate protocol 2.0.0 to 2.1.0

## Preconditions

- The target has a valid `.agent/protocol.lock.yaml`.
- The lock records protocol version `2.0.0` and entrypoint digest
  `sha256:211b285aaa41b3dc195853b9da193c1339e2e4fa57cd69cdb0c809ddbfdf3389`.
- Protocol-managed paths can be reconciled without overwriting project-owned content.
- No same-version digest fork or unresolved local divergence exists.

## Operations

1. Add the `auditable-milestone-reopening` rule to the milestone/task guidance in `AGENTS.md`:
   closed milestones may return only to restore or preserve their historical end goal, must reuse
   their milestone identity and outcome contract, must record dated evidence, and must receive only
   new task IDs.
2. Preserve all project-specific prose, active milestones, tasks, immutable IDs, source anchors, and
   decisions in `.agent/todo.md`. Do not add `Reopened` to a milestone unless evidence shows that it
   was previously closed and has now returned to active work.
3. Recognize `Reopened` as an optional milestone field with an ISO date, reason, and stable evidence
   anchor. A reopened milestone must match its latest historical ID, name, `End goal`, and
   `Close when`, and must contain at least one unfinished task whose ID does not appear in history.
4. After verification, update `.agent/protocol.lock.yaml` to version `2.1.0`, set
   `last_applied: 2.1.0`, append `2.0.0-to-2.1.0` once, and add
   `auditable-milestone-reopening` once to `managed.rules`.

## Verification

- Existing active milestone and task content is unchanged except for a justified schema
  reconciliation.
- A fixture can reconstruct a closed milestone under its historical ID, add a dated `Reopened`
  field and new task ID, and close it again without restoring completed tasks.
- A fixture with materially different end-goal work is rejected as a reopen and requires a new
  milestone ID.
- Project-owned content and unrelated paths are unchanged.
- Internal links, immutable IDs, source anchors, and target verification pass.
- A repeated 2.1.0 reconciliation produces zero diff.

## Abort behavior

Stop without advancing the lock if a precondition, ownership check, historical identity check, or
verification step fails. Revert only changes attributable to this migration; never use destructive
Git operations.
