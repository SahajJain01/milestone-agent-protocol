# Migrate protocol 2.2.0 to 2.3.0

## Preconditions

- The target has a valid `.agent/protocol.lock.yaml`.
- The lock records protocol version `2.2.0` and entrypoint digest
  `sha256:f4ddc4371b17ec6fe98c013e2f25b75519ce82497692cadee97fc704194f164b`.
- Protocol-managed paths can be reconciled without overwriting project-owned content.
- No same-version digest fork or unresolved local divergence exists.

## Operations

1. Add the `explicit-legacy-unlocked-adoption` rule to `AGENTS.md`: a missing lock is never
   synthesized during ordinary reconciliation; only a declared adoption specification plus explicit
   post-audit human authorization may adopt eligible pre-lock records.
2. Add `applied_adoptions: []` to lock state and `legacy_adoption: null` at the lock root. Existing
   locked targets do not retroactively claim legacy adoption.
3. Preserve all project-specific prose, immutable IDs, source anchors, decisions, external evidence,
   and unrelated paths.
4. After verification, update `.agent/protocol.lock.yaml` to version `2.3.0`, set
   `last_applied: 2.3.0`, append `2.2.0-to-2.3.0` once, and add
   `explicit-legacy-unlocked-adoption` once to `managed.rules`.

## Verification

- Ordinary missing-lock reconciliation remains fail-closed and cannot bypass a historical lock.
- The target lock records no adoption and retains its existing initialization and migration history.
- Project-owned content and unrelated paths are unchanged.
- Internal links, immutable IDs, source anchors, target verification, and declared digests pass.
- A repeated 2.3.0 reconciliation produces zero diff.

## Abort behavior

Stop without advancing the lock if a precondition, ownership check, or verification step fails.
Revert only changes attributable to this migration; never use destructive Git operations.
