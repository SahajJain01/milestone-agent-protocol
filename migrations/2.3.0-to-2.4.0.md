# Migrate protocol 2.3.0 to 2.4.0

## Preconditions

- The target has a valid `.agent/protocol.lock.yaml`.
- The lock records protocol version `2.3.0` and entrypoint digest
  `sha256:026428857e08b3894c17d4013e9c75bc63ad2e8277cf0f6a479e6b67e8451563`.
- Protocol-managed paths can be reconciled without overwriting project-owned content.
- `.agent/milestones/index.md` and `.agent/milestones/M-###.md` lifecycle records are absent. Any
  pre-existing path in that namespace is project-owned under 2.3.0 and requires a conflict report,
  not overwrite or implicit adoption.
- No same-version digest fork or unresolved local divergence exists.

## Operations

1. Create `.agent/milestones/index.md` with a forward-only coverage boundary at the migration
   timestamp. State that earlier closures remain Git-only unless later imported from stable,
   unambiguous evidence. Do not infer or synthesize historical milestone records during migration.
2. Add the `durable-milestone-lifecycle-archive` rule to `AGENTS.md`: the active todo owns only
   unfinished work; a milestone must receive or extend its indexed lifecycle record before leaving
   the todo; reopen and reclose cycles append archive entries while preserving the original outcome
   contract and allocating only new task IDs.
3. Reconcile `.agent/todo.md` guidance to use the archive for post-2.4.0 closure and reopening while
   preserving every active milestone, task, state, ID, source anchor, dependency, acceptance
   condition, and project-specific statement.
4. Preserve all existing decisions, external evidence, local guidance, immutable IDs, and unrelated
   paths. Do not copy completed task bodies into the archive or create frontend, visualization,
   dependency, hosting, or deployment files.
5. After verification, update `.agent/protocol.lock.yaml` to version `2.4.0`, set
   `last_applied: 2.4.0`, append `2.3.0-to-2.4.0` once, add
   `.agent/milestones/index.md` as a schema-owned managed path, and add
   `durable-milestone-lifecycle-archive` once to `managed.rules`.

## Verification

- The archive index exists, declares an honest forward-only coverage boundary, and contains no
  fabricated historical rows.
- Existing active milestone and task content is unchanged except for justified schema guidance.
- A newly closed fixture writes and indexes one lifecycle record before removing its milestone from
  the todo; a repeated reconcile adds no row or lifecycle entry.
- A pre-2.4.0 Git-only milestone is imported only when stable history unambiguously proves its
  identity, outcome contract, closure, and task IDs; ambiguous evidence aborts without reopening.
- A close/reopen/reclose fixture preserves the original milestone contract, appends ordered lifecycle
  entries, and allocates only new task IDs.
- Project-owned content and unrelated paths are unchanged, and no visualization or frontend artifact
  is introduced.
- Internal links, immutable IDs, archive schemas, source anchors, target verification, and declared
  digests pass.
- A repeated 2.4.0 reconciliation produces zero diff.

## Abort behavior

Stop without advancing the lock if a precondition, ownership check, archive consistency check, or
verification step fails. Revert only changes attributable to this migration; never use destructive
Git operations.
